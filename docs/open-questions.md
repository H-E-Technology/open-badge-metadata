# まだ決めていないこと

## 1. バッジのどこにメタデータを入れるか

OB3 の `OpenBadgeCredential` の中で、メタデータを置く場所と書き方が決まっていない。

- 候補 A: `credentialSubject.achievement` に独自の項目として足し、独自の JSON-LD コンテキストを公開する
- 候補 B: OB3 本体の項目（`name`, `criteria`, `alignment`, `resultDescription` など）にできるだけ割り当て、足りない分だけ独自項目にする

どちらにしても、独自コンテキストの URL と、どのプロファイル・版に従ったかを示す書き方が要る。
バッジの署名とコンテキストを扱う、自社の LMS 側のパッケージとあわせて決める。

## 2. OB3 本体と重なる項目をどちらで持つか

マイクロクレデンシャルの 11 項目のうち、次は OB3 本体にも同じ意味の項目がある。

| 11 項目 | OB3 の項目 |
| --- | --- |
| 1. 学習者の識別情報 | `credentialSubject.identifier` |
| 2. 名称 | `achievement.name` |
| 4. 授与機関 | `issuer` |
| 5. 発行日 | `validFrom` |

今はすべてメタデータ側に書く形にしている。二重に持つなら一致を確かめる関数が要る。
