# まだ決めていないこと

## 前提

- 項目は独自に決めない。国内の「マイクロクレデンシャルのフレームワーク 1.0」の記述子を使う。
- 「デジタル発行するためのガイドライン 3.0」の書き方は守る。そのうえで、`criteria.narrative` に文章で入る 11 記述子を、値として取り出せる形でも格納する。格納ルールは [storage-rule.md](storage-rule.md) にある。
- 発行機関、発行国、発行日、学習者、名称、内容は、ガイドライン 3.0 どおり OB 3.0 本体の項目に入れ、構造化データには重ねて持たない。

根拠にした先行事例は [prior-art.md](prior-art.md) にまとめている。

## 1. まだ確かめていないこと

このパッケージには、構造化データの型と検証、文章を作る関数、JSON-LD コンテキスト、バッジ全体に当てる JSON Schema、バッジ全体の検証、照合用のデータがある。語彙、本文の言い回し、URL は仮のものである。

手元で確かめてあるのは、JSON-LD の処理系での展開と正規化、OB 3.0 本体の JSON Schema との両立までである。次は、実物のバッジでまだ確かめていない。

- **署名付きのバッジの発行**: 自社の LMS に組み込み、構造化データ入りのバッジを署名付きで発行できるか。
- **他のウォレットでの扱い**: このルールを知らないウォレットが、構造化データ入りのバッジを取り込み、検証し、文章を表示できるか。弾くウォレットがあれば、ルールの形を見直す必要がある。
- **1EdTech の検証ツール**: OB 3.0 のバッジとして通るか。

コンテキストと JSON Schema は、試すための置き場所として GitHub Pages の `draft/` の下に置く。OB 3.0 の仕様では、検証する側が `credentialSchema` の URL から JSON Schema を取得するので、実際に開ける URL が要るためである。本番の URL は別に決める（4 章）。

## 2. 語彙

値を取り出して比べるには、選べる値をそろえる必要がある。次が決まっていない。

- **評価の方法**（`assessments.method`）: 仮に 9 種（`exam`、`assignment`、`project` など）を使っている。このまま使うか、ELM の統制語彙などに寄せるか。
- **単位やポイントの制度名**（`recognitions.scheme`）: 大学設置基準の単位、UCTS、ECTS、PDU などを、どう書き表すか。
- **レベルの枠組み名**（`levels.framework`）: 日本には全国資格枠組みが無い。「学士」「修士」などをどの枠組みの値として書くか。
- **本文の言い回し**: 区分や数値を `criteria.narrative` に書くときの書き方（[storage-rule.md](storage-rule.md) の 6 章）。今の書き方は仮のものである。言い回しを変えると、同じ構造化データから作られる文章が変わる。

## 3. 多言語のテキスト

案では、言語タグをキーにしたオブジェクトで持つ。フレームワークは、名称と発行機関だけ英語の併記を必須とし、ほかは任意としている。

- 日本語を必須にするか、どれか 1 言語あればよいとするか。
- 名称と発行機関は OB 3.0 本体の文字列項目に入るので、英語の併記をどう書くか（ガイドライン 3.0 にも決まりが無い）。

## 4. コンテキストと JSON Schema の公開先

OB 3.0 の仕様は、どちらも CORS の制限なしで公開することを求めている。URL は一度使い始めると変えられない。

- どのドメインに置くか。
- 版を URL にどう含めるか。
- バッジの署名とコンテキストを扱う、自社の LMS 側のパッケージとの分担。

## 5. 採用の働きかけ

独自に足した項目は、このルールを知らないウォレットには読めない。ほかのサービスに読んでもらうには、採用してもらう必要がある。

- 国内: マイクロクレデンシャル共同WG／日本マイクロクレデンシャル機構に、ガイドライン 3.0 の構造化版として提案するか。
- 国際: 1EdTech の拡張レジストリに登録するか。
- 提案する時期。自社で発行と読み取りを試してからにするか。

## 6. 文章だけのバッジを読むか

他の発行者がガイドライン 3.0 だけに沿って出したバッジは、`criteria.narrative` の文章しか持たない。見出しを手がかりに文章を分解して読む機能を、このパッケージで持つかどうか。

## 7. EU 勧告と修了証明書の扱い

- **EU 理事会勧告**: EU の必須 11 項目は、`eu-microcredential` プロファイルが持っている。国内フレームワークとは必須項目が違い、格納ルールの形にもなっていない。EU 向けの発行が要るなら格納ルールの形に直し、要らないなら消す。
- **修了証明書**: 国内フレームワークは、評価を伴わない修了・参加の証明をマイクロクレデンシャルの対象外としている。`completion-certificate` プロファイルの項目は確定しておらず、該当する既存のルールも見つかっていない。実際に発行している修了証と突き合わせるか、外すかを決める。
